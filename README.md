# ArrowFin — Trader Daily Snapshot · Backend service

NestJS + Prisma + PostgreSQL service that computes a trader's daily snapshot (open
positions, day P&L, risk score) and pushes new fills over a tenant-scoped WebSocket.

**Submission documents** (Background, time and LLM disclosure, security writeup, code review,
reflection): <https://github.com/jorius/arrowfin-llm-usage-docs>. Companion repository (Next.js widget):
<https://github.com/jorius/arrowfin-mt-daily-snap-fe>.

---

## What this is

A trader authenticates with their trader id and secret, receives an opaque API key,
lists their accounts, and requests the snapshot for one account. The snapshot is
computed for the current CME Globex session ("today") as of a configurable "now"
(defaults to the dataset cut, `2026-08-25T14:30:00Z`). A Socket.IO connection,
authenticated once at handshake time, pushes `fill` events for the trader's own
accounts only. A development-only endpoint simulates fills.

`broker_id` is the tenant key. Every query in this service names the tenant.
The auth model, isolation layers and PII handling are written up in the submission repository: <https://github.com/jorius/arrowfin-llm-usage-docs/blob/main/SECURITY.md>.

## Running it locally

Prerequisites: Node 24, PostgreSQL 16+ (18 used here), the assessment dataset
folder (not part of this repository, see below).

| Variable | Purpose | Default |
| --- | --- | --- |
| `DATABASE_URL` | Postgres connection string | required |
| `PORT` | HTTP + WebSocket port | `3001` |
| `CORS_ORIGIN` | Allowed browser origin | `http://localhost:3000` |
| `SNAPSHOT_NOW` | Instant treated as "now" (ISO 8601) | `2026-08-25T14:30:00Z` |
| `API_KEY_TTL_HOURS` | API key lifetime | `12` |
| `DEV_FILLS_ENABLED` | Registers `POST /dev/fills` (never in production) | `false` |
| `DEV_TRADER_SECRET` | If set, the seed gives every trader this secret (demo only) | unset |
| `DATASET_DIR` | Folder containing the CSVs for the seed | `../dataset` |
| `WS_PING_INTERVAL_MS` | Socket.IO heartbeat: how often the server pings each client | `25000` |
| `WS_PING_TIMEOUT_MS` | How long a client may stay silent after a ping before the server drops it | `20000` |
| `WS_CONNECT_TIMEOUT_MS` | How long a handshake may take before the server gives up | `45000` |
| `SWAGGER_ENABLED` | Serves `/docs` and `/docs-json`; ignored (off) when `NODE_ENV=production` | `true` |

```bash
cp .env.example .env            # then edit DATABASE_URL
npm ci
npx prisma migrate deploy       # creates the schema
npm run seed                    # loads the CSVs from DATASET_DIR, creates trader credentials
npm run start:dev               # http://localhost:3001
npm test                        # unit tests (vitest)
```

**Dataset handling.** The CSVs are treated as production-grade customer data. They
are never committed: `*.csv` and `dataset/` are ignored, and a pre-commit hook
(`.githooks/pre-commit`, installed via `git config core.hooksPath .githooks`)
refuses any commit that stages a CSV or a `.env` file. The seed reads them from
`DATASET_DIR` at run time only. Trader secrets generated by the seed are written to
`.local/trader-secrets.json` (ignored) unless `DEV_TRADER_SECRET` is set.

## Architecture

Layering (NestJS 12, ESM):

| Folder | Responsibility |
| --- | --- |
| `src/controllers/` | HTTP controllers, the Socket.IO gateway, the API-key guard, the dev-only fills module |
| `src/application/` | Use cases, repository ports, DTOs, `TenantContext` / `Principal` |
| `src/services/` | Business rules with no I/O: position ledger, P&L, risk, session clock, secret hashing, API-key generation |
| `src/infrastructure/` | Prisma client and tenant-scoped repositories, validated env config, the CSV seed |

Design document: [`docs/superpowers/specs/2026-09-14-trader-daily-snapshot-design.md`](./docs/superpowers/specs/2026-09-14-trader-daily-snapshot-design.md).

Why `broker_id` is denormalized onto `accounts`, `fills` and `api_keys`: the dataset
carries the tenant only on `traders`. With the tenant on every row, each table can be
filtered with a single `WHERE broker_id = $1`, the composite foreign keys
`accounts(trader_id, broker_id) → traders(id, broker_id)` and
`fills(account_id, broker_id) → accounts(id, broker_id)` reject rows that disagree
with their parent's tenant, and row-level security can be attached without joins.

### The index worth explaining

`fills(broker_id, account_id, filled_at)`. The snapshot replays every fill of one
account in time order (positions carry across sessions) and then narrows to today's
session. Leading with the tenant key means a tenant-scoped query descends straight
into that tenant's slice of the index and range-scans by account and time. It never
touches another tenant's pages, which is a performance property and an isolation
property at once. The live path (append a fill, re-read one account) uses the same
index.

### Snapshot algorithm

1. Load the account by `(id, broker_id, trader_id)`; 404 if absent.
2. Load all fills for `(broker_id, account_id)` with `filled_at <= now`, ordered.
3. Compute the Globex session containing `now` (17:00 America/Chicago open).
4. Replay fills through an average-cost ledger per instrument; realized P&L and
   commissions are accumulated only for fills inside the session.
5. Unrealized = (mark − avg) × net qty × point value, signed by side.
6. Risk = `min(100, |Σ notional| / balance × 100)`; a zero balance with exposure
   scores 100. Level `HIGH` above 75, `ELEVATED` above 50, otherwise `LOW`.

## API

| Method | Path | Auth | Response |
| --- | --- | --- | --- |
| GET | `/health` | none | `{ "status": "ok" }` |
| POST | `/auth/api/key` | none | 201 `{ apiKey, expiresAt, principal: { traderId, brokerId }, portalName }` · 401 invalid · 403 suspended |
| DELETE | `/auth/api/key` | Bearer | 204, revokes the calling key |
| GET | `/me/accounts` | Bearer | `{ accounts: [{ id, accountNumber, accountType, status }] }` |
| GET | `/accounts/:accountId/snapshot` | Bearer | 200 snapshot · 404 if the account is not the caller's |
| POST | `/dev/fills` | none, dev only | 201 `{ fill }` and a `fill` WebSocket event |

WebSocket (Socket.IO): connect with `auth: { apiKey }`. The server verifies the key
once at handshake, joins the socket to rooms for the caller's own accounts, and emits
`fill` events `{ id, accountId, symbol, side, quantity, price, filledAt }`. There is
no client-to-server subscribe message.

Right after a socket is admitted the server emits one `hello` event to that socket only:
`{ serverTime, pingIntervalMs, pingTimeoutMs, connectTimeoutMs, transport, rooms }`.
`serverTime` is the replay clock (see `SNAPSHOT_NOW`), the three intervals are the effective
heartbeat settings read from the environment, `transport` is the Engine.IO transport in use and
`rooms` is how many account rooms the socket was joined to. The payload carries configuration
only: no account ids, no names, no balances. The widget shows these values in its Connection
panel, which is also how a demo can show what happens when `WS_PING_TIMEOUT_MS` is lowered.

### API documentation

- **OpenAPI / Swagger.** The service serves an interactive UI at `/docs` and the OpenAPI 3
  document at `/docs-json` (for example
  <https://arrowfin-mt-daily-snap-svc-staging.up.railway.app/docs>). Every route, status code
  and response schema is declared explicitly in the controllers and the classes under
  `src/application/dto/*.response.ts`; the bearer scheme is named `api-key`. Paste an `afk_…`
  key into "Authorize" to call the guarded routes from the UI. The docs are controlled by
  `SWAGGER_ENABLED` (default `true`) and are always off when `NODE_ENV=production`, the same
  kill-switch pattern as the dev fill simulator.
- **Postman.** Import `postman/arrowfin-daily-snapshot.postman_collection.json` and one of
  `postman/arrowfin-staging.postman_environment.json` or
  `postman/arrowfin-development.postman_environment.json` (or keep the collection's default
  `baseUrl` of `http://localhost:3001`). Set the `secret` variable to the trader's secret
  (never stored in the repository), then run the collection top to bottom with the Collection
  Runner: Health, Issue API key (stores `apiKey`), wrong-secret 401, list accounts, snapshot,
  foreign account 404, simulate fill (dev only), revoke. From the terminal:
  `npx newman run postman/arrowfin-daily-snapshot.postman_collection.json --env-var secret=<secret> --env-var baseUrl=<url>`.

### Simulating live fills

```bash
DEV_FILLS_ENABLED=true npm run start:dev
curl -X POST http://localhost:3001/dev/fills \
  -H 'content-type: application/json' \
  -d '{"account_id":"ACC-1006","instrument_symbol":"MES","side":"BUY","quantity":2,"price":5643.25,"commission_usd":1.40}'
```

## Deployment

Two Railway environments, `staging` (the public demo, playing the production role) and
`development` (an isolated sandbox), each with its own Postgres, both built from `main` by
the GitHub integration; the widget is on Netlify at
<https://arrowfin-mt-daily-snap.netlify.app> pointing at staging. Details, variables and the
seeding procedure are in [`docs/deployment.md`](./docs/deployment.md). Demo credentials are
shared out of band, never through the repository.
