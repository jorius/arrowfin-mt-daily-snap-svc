## What this is

A trader authenticates with their trader id and secret, receives an opaque API key,
lists their accounts, and requests the snapshot for one account. The snapshot is
computed for the current CME Globex session ("today") as of a configurable "now"
(defaults to the dataset cut, `2026-08-25T14:30:00Z`). A Socket.IO connection,
authenticated once at handshake time, pushes `fill` events for the trader's own
accounts only. A development-only endpoint simulates fills.

`broker_id` is the tenant key. Every query in this service names the tenant.
See [SECURITY.md](./SECURITY.md) for the auth model, isolation layers and PII handling.

## Running it locally

Prerequisites: Node 24, PostgreSQL 16+ (18 used here), the assessment dataset
folder (not part of this repository, see below).

| Variable | Purpose | Default |
| --- | --- | --- |
| `DATABASE_URL` | Postgres connection string | required |
| `PORT` | HTTP + WebSocket port | `3001` |
| `CORS_ORIGIN` | Allowed browser origin | `http://localhost:3000` |
| `SNAPSHOT_NOW` | Instant treated as "now" (ISO 8601) | `2026-08-25T14:30:00Z` |
| `API_KEY_TTL_HOURS` | API key lifetime | `12` |
| `DEV_FILLS_ENABLED` | Registers `POST /dev/fills` (never in production) | `false` |
| `DEV_TRADER_SECRET` | If set, the seed gives every trader this secret (demo only) | unset |
| `DATASET_DIR` | Folder containing the CSVs for the seed | `../dataset` |

```bash
cp .env.example .env            # then edit DATABASE_URL
npm ci
npx prisma migrate deploy       # creates the schema
npm run seed                    # loads the CSVs from DATASET_DIR, creates trader credentials
npm run start:dev               # http://localhost:3001
npm test                        # unit tests (vitest)
```

**Dataset handling.** The CSVs are treated as production-grade customer data. They
are never committed: `*.csv` and `dataset/` are ignored, and a pre-commit hook
(`.githooks/pre-commit`, installed via `git config core.hooksPath .githooks`)
refuses any commit that stages a CSV or a `.env` file. The seed reads them from
`DATASET_DIR` at run time only. Trader secrets generated by the seed are written to
`.local/trader-secrets.json` (ignored) unless `DEV_TRADER_SECRET` is set.

Why `broker_id` is denormalized onto `accounts`, `fills` and `api_keys`: the dataset
carries the tenant only on `traders`. With the tenant on every row, each table can be
filtered with a single `WHERE broker_id = $1`, the composite foreign keys
`accounts(trader_id, broker_id) → traders(id, broker_id)` and
`fills(account_id, broker_id) → accounts(id, broker_id)` reject rows that disagree
with their parent's tenant, and row-level security can be attached without joins.

### The index worth explaining

`fills(broker_id, account_id, filled_at)`. The snapshot replays every fill of one
account in time order (positions carry across sessions) and then narrows to today's
session. Leading with the tenant key means a tenant-scoped query descends straight
into that tenant's slice of the index and range-scans by account and time. It never
touches another tenant's pages, which is a performance property and an isolation
property at once. The live path (append a fill, re-read one account) uses the same
index.

### Snapshot algorithm

1. Load the account by `(id, broker_id, trader_id)`; 404 if absent.
2. Load all fills for `(broker_id, account_id)` with `filled_at <= now`, ordered.
3. Compute the Globex session containing `now` (17:00 America/Chicago open).
4. Replay fills through an average-cost ledger per instrument; realized P&L and
   commissions are accumulated only for fills inside the session.
5. Unrealized = (mark − avg) × net qty × point value, signed by side.
6. Risk = `min(100, |Σ notional| / balance × 100)`; a zero balance with exposure
   scores 100. Level `HIGH` above 75, `ELEVATED` above 50, otherwise `LOW`.

## API 🤖

| Method | Path | Auth | Response |
| --- | --- | --- | --- |
| GET | `/health` | none | `{ "status": "ok" }` |
| POST | `/auth/api/key` | none | 201 `{ apiKey, expiresAt, principal: { traderId, brokerId }, portalName }` · 401 invalid · 403 suspended |
| DELETE | `/auth/api/key` | Bearer | 204, revokes the calling key |
| GET | `/me/accounts` | Bearer | `{ accounts: [{ id, accountNumber, accountType, status }] }` |
| GET | `/accounts/:accountId/snapshot` | Bearer | 200 snapshot · 404 if the account is not the caller's |
| POST | `/dev/fills` | none, dev only | 201 `{ fill }` and a `fill` WebSocket event |

WebSocket (Socket.IO): connect with `auth: { apiKey }`. The server verifies the key
once at handshake, joins the socket to rooms for the caller's own accounts, and emits
`fill` events `{ id, accountId, symbol, side, quantity, price, filledAt }`. There is
no client-to-server subscribe message.

DEV_FILLS_ENABLED=true npm run start:dev
